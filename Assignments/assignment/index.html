Why Indexing is Essential in MongoDB

Without an index, MongoDB performs a Collection Scan (COLLSCAN), reading every single document from disk. With an index on rollNo, MongoDB performs an Index Scan (IXSCAN) using a balanced B-Tree, jumping straight to the document in O(log N) time.

Index on rollNo: ENABLED (Unique)
Stage: COLLSCAN

Without Index (Linear Scan)

Docs Examined: 50,000 docs
Keys Examined: 0 keys
Execution Time: 38.40 ms
Time Complexity: O(N)
Disk I/O Cost: Reads All Blocks

MongoDB sequentially checks every record from document #1 to document #50,000 until match is confirmed.

Stage: IXSCAN → FETCH

With Index on rollNo (B-Tree)

Docs Examined: 1 doc
Keys Examined: 1 key
Execution Time: 0.05 ms (768x faster)
Time Complexity: O(log N)
Disk I/O Cost: Target Block Only

MongoDB traverses the rollNo B-Tree in ~15 pointer hops, directly fetching the exact document.
